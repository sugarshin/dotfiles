# HTML Explainer

技術解説を「やさしい読み物スタイルの1枚 HTML」として、**毎回ブレない同じスタイル**で生成する。
見た目を一から作るスキルではない。このスキルのディレクトリにある `template.html` の `<style>`・部品・`<script>` を
**そのまま使い回し**、配色や部品を即興で足さないことで再現性を担保する。

## Input

$ARGUMENTS

- `.html` で終わるパスが含まれていれば、それを**ローカル出力先**として扱い、残りを題材とする。
- 題材から「何を・誰向けに」解説するか読み取れないときだけ、書き始める前に 1 回確認する。

## 責務の境界

| やること | やらないこと |
|---------|------------|
| 前提知識ゼロ向けの技術解説 HTML を毎回同じスタイルで作る | 凝った Web アプリ・LP・ダッシュボード |
| `template.html` の `<style>` と部品を使い回す | 配色・部品を即興で足す |
| たとえ話 + 図 + 実コードで噛み砕く | 用語の羅列、読み手が知っている前提での説明 |

## スタイルの 4 本柱（最重要）

この 4 つを守れば「初心者が怖がらずに読めるやさしい解説」になる。

### 1. たとえ話で噛み砕く

- 記事の**中心になる概念**は、日常の場面に置き換えて `.tatoe`（黄）で説明する。
  - 例: Cookie =「自動で見せるリストバンド」、BFF =「ホテルのコンシェルジュ／金庫」。
- 脇役の用語までボックスにしない。本文中の一言の言い換え（「〜、つまり〜のこと」）で済ませる。
- たとえ話は理解の補助であって誤魔化しではない。**たとえた直後に `.word` の正確な定義かコードで裏取りする。**
- 一つのたとえを**記事全体で一貫させる**（登場人物を最後まで使い回す）。

### 2. 物語仕立ての章構成

- 順序に意味がある題材（処理の流れ・歴史・段階的な設計）は `h2 > span.step` で「第1章・第2章…」と旅のように進める。
  順序が無い題材は番号なしの `h2` にする。
- 各章の冒頭で**前章を受ける一文**を置き、用語が前触れなく登場しないようにする。
- 章末に `.recap` で **3〜4 行のまとめ**を置く。
- 章の転換点では `.big-q` で「読み手が自然に抱く疑問」を大きく出し、次章への推進力にする。

### 3. 淡い地色のボックス

- 種別ごとに**淡い地色のカード**で区別する（細枠だけにしない）。
  - `.tatoe`（黄・たとえ話）/ `.word`（青・用語定義）/ `.warn`（赤・注意/落とし穴）/ `.point`（緑・要点）。
- 見出しは `span.label` に書く（例: `たとえ話：文化祭の出し物チェック`、`なぜダメ？`、`ここだけ覚えればOK`）。
  `.word` は `span.term` に用語名を書く（先頭に絵文字を付けてよい）。左のアイコン（🏠 / ⚠️ / 💡）は CSS が付ける。
- ボックスを乱発しない。「立ち止まって読んでほしいところ」だけに使う。

### 4. 実コードの引用

- コードの話をするときは**必ず本物のコードを `<pre>` で見せる**。説明だけで終わらせない。
- 出す前に「1 行ずつ読まなくて大丈夫」と**先に安心させる**。
- `.k`（キーワード）/ `.s`（文字列）/ `.f`（関数）/ `.c`（コメント）の `<span>` で手動シンタックスハイライトする。
- 落とし穴があるなら **🛑 NG → ✅ OK の対比**で見せる。NG / OK を示すコメント行は `.ng`（赤字）/ `.ok`（緑字）で包む。
- `<pre>` 内の `<` `>` `&` は `&lt;` `&gt;` `&amp;` にエスケープする（JSX や型引数で崩れやすい）。
- 説明のための省略（`// ...`）・整形はしてよいが、**実在しないコードは書かない**。
  引用元（リポジトリ内パスや URL）は `<pre>` 1 行目のコメントか `footer` の出典に書く。

## 配色

`template.html` の `<style>` に定義済み。**色を即興で増やさない。本文に `style` 属性で色や余白を書かない**（`<style>` にある部品だけで表現する）。ライトテーマ固定。

`:root` の主な色:

| 役割 | 変数 | 値 |
|------|------|-----|
| 背景 | `--bg` | `#fdfcfa` |
| 本文 | `--ink` | `#2d2a26` |
| 補足テキスト | `--soft` | `#6b6358` |
| 枠線 | `--line` | `#ece6dd` |
| アクセント（見出し・重要語・注意） | `--accent` / `--accent-soft` | `#e07a5f`（テラコッタ）/ `#fceee9` |
| 用語 | `--blue` / `--blue-soft` | `#3d7ea6` / `#eaf3f8` |
| 要点 | `--green` / `--green-soft` | `#5b8c5a` / `#ecf4eb` |
| たとえ話 | `--yellow-soft` / `--yellow-line` | `#fdf6e3` / `#e8d9a8` |
| フロー図の中継ノード | `--purple` / `--purple-soft` | `#7c6aa8` / `#f1edf7` |
| コード背景 | `--code-bg` | `#2d2a32` |

- ボックスの枠線・マーカー（`#fde6a8`）・コードの文字色などは、各部品の CSS に直接書かれている。

- コードフォントは `"SF Mono", "JetBrains Mono", Menlo, Consolas, monospace`。

## マークアップ部品（`template.html` に見本あり）

**新しい部品を即興で作らない。** 使わない部品の見本は消す。

| 部品 | クラス / 構造 | 用途 |
|------|--------------|------|
| ヒーロー | `header.hero`（`.emoji` / `h1` / `.sub` / `.who`）。`.wrap` の外に置く | 記事冒頭。絵文字＋タイトル＋想定読者バッジ |
| 3行まとめ | `.tldr > .ttl + ol` | 冒頭の TL;DR |
| 章見出し | `h2 > span.step` | `第N章` の章番号（**順序に意味があるときだけ**）。番号なしの見出しは先頭に絵文字 |
| 小見出し | `h3` | 章の中の区切り |
| リード | `h2 + p.lead` | 見出し直後の一言リード |
| たとえ話 | `.tatoe > span.label + p` | 用語を身近な比喩に置き換える（黄） |
| 用語定義 | `.word > span.term + p` | 正確な定義（青） |
| 注意・落とし穴 | `.warn > span.label + p` | ハマりどころ（赤） |
| 要点 | `.point > span.label + p` | ここだけ押さえればOK（緑） |
| 章まとめ | `.recap > .ttl + ul` | 章末の点線吹き出しまとめ |
| 大きな問い | `div.big-q` | 章の転換点で読み手の疑問を大きく出す |
| 区切り線 | `hr.sep` | 章と章、章と `.big-q` の間 |
| フロー図 | `.flow > .row > .node + .arrow`、任意で `.caption` | 一方向の流れを図示。`.node` の色は `.blue` / `.purple` / `.green` / `.neutral`。`.arrow` の中身は空か `span.lbl`（矢印記号は CSS が付けるので `→` を書かない）。1 つの `.row` にノードは 3 個まで（折り返すと矢印が行末に取り残される） |
| コード | `<pre>` + `.k/.s/.f/.c`、NG/OK のコメント行は `.ng/.ok` | 手動シンタックスハイライト |
| インラインコード | `code.inline` | 文中のコード片 |
| テーブル | `.tablewrap > table`（行見出しの列は `td.key`） | 用語定義・比較・年表 |
| マーカー / 太字 | `.mark` / `strong` | 最重要の一文 / 要点の語 |
| 引用 | `blockquote` | 引用元の文をそのまま引く |
| 箇条書き | `ul.plain` | ボックスの外の箇条書き |
| フッター | `footer` | 出典 |
| 左固定 TOC | `nav.toc#toc-nav` + 末尾 `<script>` | 章もくじ。**中身は書かない**（下記） |

- 760px 以下ではフロー図が縦積みになり、矢印が `↓` に変わる。

### 左固定 TOC（章もくじ）

- 末尾の `<script>` が `.wrap` 内の `h2` を走査し、`id` を振って `nav.toc#toc-nav` にもくじを自動生成する。
  スクロール位置に合わせて現在の章を `.active`（テラコッタ）でハイライトする。
- **`h2` を普通に書くだけでよい。** `nav.toc` の中身を手で書かない（章の差し替えに追従しなくなる）。
- `.step` 付きの見出しは `第N章 — 見出し` の形で並ぶ。
- 幅 1200px 以上でだけ左端に表示し、それ未満では非表示（本文 1 カラムのまま）。`h2` が 0 個なら出さない。

## 解説の組み立て順

いきなり本題に入らない。

1. **TL;DR** — `.tldr` で「3行でいうと」を先に渡す。
2. **準備運動** — 本題で使う言葉を `.tatoe` ＋ `.word`（用語が多ければ `.tablewrap`）で先にそろえる。
3. **本題を物語として進める** — 動機と解決した問題を軸に章を立てる。順序に意味があれば `第N章`。
4. **章どうしを言葉でつなぐ** — 章冒頭で前章を受け、章末は `.recap` で締め、`hr.sep` で区切る。
5. **転換点は `.big-q`** — 読み手が抱く「あれ？」を出して次章へ。
6. **実例を 1 つ端から端まで通す** — コードの題材で落とし穴があれば 🛑NG → ✅OK を `<pre>` で対比する。
7. **おわりに冒頭の問いへ回収する** — `.big-q` で問いを再掲し、`.point` で結論と読み手が次にやる行動 1 つを示す。

- **推測は推測と明示する。** 裏取りしていない主張は「これは推測」と断る。

## やってはいけないこと

| ❌ NG | なぜ |
|------|------|
| 用語をいきなり出す（準備運動なし） | 初心者が置いていかれる。依存する言葉は先に定義する |
| たとえ話だけで終わる | 誤解を生む。直後に定義かコードで裏取りする |
| 脇役の用語まで全部ボックスにする | 騒がしくなり、本当に止まってほしい箇所が埋もれる |
| コードの話なのにコードを見せない | 4 本柱④に反する |
| コードを捏造する / 引用元を書かない | 読み手が裏取りできない。省略・整形は可、事実は曲げない |
| 配色・部品を即興で足す / `<style>` や `style` 属性で見た目を変える | 再現性が崩れる |
| 章番号を順序の無い内容に振る | 存在しない順序を暗示する |
| 分岐する依存関係を `.flow` で描く | 左から右の 1 列が、存在しない実行順序を暗示する |

## 実行手順

### 1. 題材を理解する

- コード・仕組み・リンク先・記事を読み込み、前提知識から実例・落とし穴まで把握する。
  実コードを引用する以上、**引用元を必ず実際に読む**。
- **題材がコード（ファイル・ディレクトリ）なら 1 行ずつの逐次解説にしない。**
  登場人物（モジュール・レイヤー・主要関数）を先に地図化し、細部の引用はその地図の上に置く。
  - 一方向に流れる処理・データフロー → `.flow`
  - 分岐する依存グラフ・静的なモジュール関係 → `.tablewrap` の表か `.point`

### 2. HTML を組み立てる

- `template.html` を Read し、それをベースに書く。
- **変えないもの**: `<meta>`、`<style>`、`nav.toc#toc-nav`（空のまま）、末尾の `<script>`。
- **差し替えるもの**: `<title>`（`【タイトル】 ── 【サブタイトル】` の形）、`header.hero`、`.wrap` の中身。
  使わない部品の見本と、先頭の使い方コメントは消す。
- `<html>` / `<head>` / `<body>` は**足さない**。Artifact の publish 時に skeleton で包まれるため。
  ローカルで開いてもブラウザが補完し、先頭の `<meta charset="UTF-8">` で文字化けしない。
- 「組み立て順」に沿って本文を書き、最後に次を見直す。
  - 「4 本柱」と「やってはいけないこと」
  - `【` が残っていない（`grep -n '【' <path>` で 0 件）
  - 同じ内容のボックスや段落が重複していない（章を書き足すうちに貼り直しが起きやすい）

### 3. 書き出す

- **保存先**: 引数で `.html` パスが指定されていればそのパス、なければ `~/.claude-works/html-explainer-<YYYYMMDD>-<topic>.html`。
  `<topic>` は題材を表す短い kebab-case（例: `jwt-cookie-history`）。Artifact として公開する場合もこのファイルを元にする。
- **公開方法**: 既定は **A. Artifact**。次のどれかに当てはまるときは **B. ローカルのみ**にする。
  - 引数で `.html` パスが指定された
  - ユーザーが共有 URL を作りたくない・社外秘だと示した
  - Artifact ツールが使えない
- **A の場合は書き出す前に** `Artifact` の `quickstart` を `intent: "other"`、`design_systems: false` で呼ぶ。
  型・デザインシステム・デザイン指針を勧められても採用せず、`template.html` の見た目を保つ（このスキルの目的は毎回同じ見た目）。

### 4. 表示を確認する

- chrome-devtools MCP（または playwright MCP）が使えるなら、書き出したファイルを `file://` で開き、
  **幅 1280px と 400px** でスクリーンショットを撮って次を確認する。
  - ボックスの地色とアイコン、コードのハイライト（`.ng` 赤字 / `.ok` 緑字）が出ている
  - 400px でフロー図が縦積みになり、ページ全体が横スクロールしない
  - 1280px で左に TOC が出て、見出しと一致している
- 崩れていたら本文側のマークアップを直す（`<style>` は触らない）。
- MCP が使えず確認できなかったときは「表示確認は未実施」と報告する。確認していないのに確認済みと言わない。

### 5. 公開する / 開く

- **A. Artifact**: 保存したファイルを publish する。`favicon` は hero の `.emoji` と同じ絵文字、
  `description` は「〜を〜向けに解説する読み物」の 1 文。同じ会話での修正は同じファイルを直して再 publish し、URL を保つ。
  URL とローカルのパスを両方伝える。
- **B. ローカルのみ**: `open <path>` でブラウザ表示し、パスを伝える。
